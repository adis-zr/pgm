# Incumbent-first construction and deadline coordination

This round starts from review commit `607631adba2b68c68880d3ed330bd680b2c5b285` and preserves the accepted default. The prior measured implementation is `d33d40a`; the consolidated same-round benchmark baseline remains `f664ee7`.

## Scheduling change

Automatic policy version `structural-portfolio-3` defers optional quotient construction until after the incumbent block attempt. The old rule inferred that an unaffordable dense identity forecast justified spending a quarter of the remaining time on compression. The forecast establishes neither the construction cost nor the quality of that unbuilt representation. The revised rule keeps the incumbent's remaining allowance intact. After an early incomplete return, quotient remains available with the ordinary remaining-budget fallback allowance (1.0 rather than the old preemptive 0.25).

Existing forest, bipartite-stream, physically admitted exact-contraction and checked pairwise-response precedence remain unchanged. No benchmark names, family labels or exposure labels enter the decision. No forecast rates, thresholds, native kernels, estimators or certificate formulas are fitted or changed. Accepted and experimental policy implementations are unchanged.

The prospective risk budget remains structural 0, block delta/2, quotient delta/4 and response delta/4. Each backend is attempted at most once. Selection does not inspect previously benchmarked outcomes. Every published coordinate must pass the existing original-coordinate, positive-mass, interval and cleanup checks. Full preservation is empirical: the different PAC allocation and early structural/response attempts still distinguish automatic from accepted.

The prior full panel has no quotient-first completed request. It does have a partial answer on `1qt9` (15 of 1,230 coordinates) that may be lost if the primary route consumes the allowance. The new report must expose partial-coordinate changes, even when complete-request preservation passes. This is a known tradeoff, not an undisclosed failure or a reason to add an instance exception.

## Deadline coordination

The worker and controller already use an absolute monotonic attempt deadline. The supervisor now receives that same timestamp, so interpreter startup and a relative timeout cannot extend its computation window. An expired absolute deadline refuses before spawning. Existing cleanup ownership verification and terminal acceptance remain intact; cleanup wait allowances and the request's final reserve are not enlarged or shortened.

Obsolete wall-clock parsing is removed from ownership reconciliation: identity remains the process id plus creation time and verified parent chains. The public API prepares its suppressed-row inventory before the authoritative final sample, so deadline suppression does not allocate O(K) rows after that sample. The CLI preserves `api_wall_s` and `api_hard_deadline_respected` before recording its own publication timing. This separates API timing from later conversion, encoding and output staging.

No user-space program can promise an exact physical return time under arbitrary OS stalls. Every elapsed field remains truthful, and late publication is still suppressed. The benchmark's prospective refusal rule distinguishes a failed, clean, zero-row deadline refusal from a late published answer. The former remains an incomplete request; the latter fails validity. The outer 20-second supervision and all ownership checks remain in force.

Native setup is qualified before timing; input, source and active executable identities are checked before and after every cell. No synthetic input enters the performance panel; tiny independent fixtures test correctness only.
