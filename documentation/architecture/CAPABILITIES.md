## Cheap pre-screens that do not inspect benchmark names

Use task semantics and structural facts only. The screen may decline or prioritize a route; it must not stand in for that route's checked recognizer.

1. Original-cardinality and evidence-sliced scope scan: number of free variables, original query count, maximum effective arity, explicit table entries, factors and components. Poll while scanning and charge the data structures.
2. For effective arity <=2, build the simple graph once. Acyclicity prioritizes forest; all binary plus bipartiteness admits a stream forecast. Record component bipartition sizes and an event/working-memory upper estimate before execution.
3. Empty evidence + exactly one nonempty factor per variable is a necessary source-DAG screen. Do not equate UAI `BAYES` spelling with applicability or exact row normalization.
4. Sparse support count and affordable guarded elimination-volume estimates can distinguish support/identity candidates from infeasible native contractions. Table density alone does not prove small intermediate support.
5. Strict positive factors + effective pairwise scopes is a necessary spectral screen. The actual spectral gap certificate still costs work and can refuse. Spectral refusal is not a slow-mixing proof.
6. Recognize accepted signed/layered/ancestral structures with their existing checked routines; avoid paying for all optional constructor families before the existing baseline can run.

## Proposed first clean public boundary

Use one public `pgm.infer(request)` / CLI with immutable request and result types. Retain several internal backends and explicit capability metadata. An example contract:

- `InferenceRequest`: bound model/evidence source; original singleton inventory (or explicitly supported finite-query type); accuracy mode; exact rational epsilon/delta; seed; one absolute monotonic deadline; process-tree memory allowance.
- `Backend.screen(task, context) -> Eligibility`: supported/declined/unknown, structural facts and checked assumptions, predicted physical work/memory, charged elapsed work. No publication.
- `Backend.run(task, context, allowance) -> BackendResult`: typed terminal status, original-coordinate bounds/points, guarantee, positive-mass witness, backend trace and resources. A refused optional route never invalidates the request.
- `InferenceResult`: COMPLETE/PARTIAL/ZERO_EVIDENCE/UNSUPPORTED/INVALID_TASK/RESOURCE_LIMIT/CERTIFICATE_DEFECT; requested inventory and per-row guarantee; actual route/attempt trace; elapsed and memory accounting; binding and certificate provenance.

A backend that emits fixed-epsilon intervals may still satisfy a tighter request on a particular input, but the common checker must test the actual endpoints and point. It cannot silently claim that the backend was designed for arbitrary epsilon. EXACT_RATIONAL must require exact represented values, not merely a mathematically exact floating algorithm. Legacy structural and CBI/SF/H4 paths do not generally supply the same Z contract.

The common publication gate must check exactly the requested coordinate inventory, source/evidence binding, [0,1] interval geometry, endpoint radius <=epsilon, positive-mass justification, and actual guarantee mode. Do not overwrite a route's native point with midpoint without rechecking the J-box/simplex contract. Preserve observed point masses explicitly if the public inventory includes them; existing engines differ on whether observed rows are returned.

One request owns the statistical failure budget. If more than one statistical backend can publish or its results can influence selection, allocate disjoint/summable shares prospectively and retain them in the trace. Deterministic backend attempts consume no delta but still consume time and memory. Merely taking the best of independently run full-delta streams is not a valid full-delta library result.

## Code layout and migration order

A practical first structure is:

```
src/pgm/
  __init__.py, api.py, __main__.py
  request.py, result.py, validation.py
  io/uai.py
  planning/features.py, registry.py, switchboard.py
  runtime/budget.py, worker.py
  backends/structural.py, blockres.py, quotient.py, response.py
  certificates/...
tests/                 # algebra, malformed-input, binding and resource regressions
benchmarks/external/   # frozen external manifests, protocols, benchmark runners
research/              # experiment-only recipes/docs, never imported by pgm.infer
```

Use adapters around the existing implementations first; then move their definition closures into algorithm namespaces while compatibility shims keep historical reproduction working. Do not move all files and change algorithms in one unverifiable step. Bare imports named `core`, `solve`, `task`, etc. and global rate/memory state make isolated subprocess adapters safer for the first consolidation; an in-process wrapper must solve module ownership and reentrancy rather than rely on `sys.path` insertion order.

The older `evaluate.py` worker includes an exact brute-force oracle when total state count <=4096, and lacks the newer staged-publication boundary. Calling it is useful as a reference, but a production adapter should call the backend directly in its own worker, normalize and validate the result, then apply the common deadline/output commit. The parent must refuse late output based on its own end-to-end receipt, not trust a child's relative timer. Benchmark all of this wrapper work.

## Acceptance boundaries

The actual public switchboard is the scored arm. Keep standalone backend runs as diagnostic references only. The primary acceptance benchmark is the full external libDAI suite, with every previously exposed task labelled regression/development; holdout inputs must be selected and committed without examining their solver outcomes, and become exposed after first use. Synthetic models remain important correctness/adversarial controls but do not enter the external performance denominator.

A passing first integration must recover the demonstrated legacy DBN/support opportunities and preserve accepted production completions without a model-name dispatch table. Failure to meet broad libDAI dominance must be reported as an empirical failure or incomplete goal, not repaired in the table by unioning standalone successes. H4/SF/CBI cannot be advertised as generic UAI-integrated until their actual adapters and whole-task contracts exist.
