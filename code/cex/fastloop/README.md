# CQR fast theory–implementation–measurement loop (harness v3)

Infrastructure only (`cex/fastloop` and `cex/cqr_amend` are in no candidate inventory scope). Protocol: `pgm-records/docs/handoff-received-2026-11-18-cqr-fast-iteration/`; repairs after the A1 review: `docs/review-received-2026-11-18-cqr-a1-fastloop/`; repairs after the repair-2 review (CQR-AF2-03..07): `docs/review-received-2026-11-18-cqr-a1-fastloop-repair2/`.

| step | command (from the CANDIDATE worktree's `code/`) | cap |
|---|---|---|
| pin the development manifest (once per version) | `python cex/fastloop/manifest.py materialize --baseline <ACCEPTED_BUILD> --out <RECORDS>/fastloop/manifest_vN` | — |
| prepare the authenticated truth cache + its TRUSTED PREPARATION INDEX (once, supervised) | `python cex/fastloop/truth_prep.py --manifest <MANIFEST> --baseline <ACCEPTED_BUILD>` | recorded |
| calibrate (once; R0 anchor + TYPED reference measurements of the size ladder; pins the change-specific pair; an ERROR_UNMEASURED reference never qualifies a rung) | `python cex/fastloop/calibrate.py --manifest <MANIFEST> --baseline <ACCEPTED_BUILD> --out <RECORDS>/fastloop/calibration_N` | 600 s |
| harness controls battery (after any harness change) | `python cex/fastloop/controls.py --out <RECORDS>/fastloop/controls_N --baseline <ACCEPTED_BUILD> --manifest <MANIFEST>` | — |
| smoke subset (while editing) | `python cex/fastloop/run.py --manifest <MANIFEST> --candidate . --baseline <ACCEPTED_BUILD> --out <RUN_DIR> --mode smoke` | 60 s target |
| full development run (every meaningful change) | `python cex/fastloop/run.py --manifest <MANIFEST> --candidate . --baseline <ACCEPTED_BUILD> --out <RUN_DIR> --mode full --hypothesis HYPOTHESIS.json --label "<change>"` | 300 s ALL-IN (identity, git, workers, verification, truth, controls, cleanup, report); 12 s finalization reserve inside it |

Launch every run as ONE charged job: `python -m gbidi.supervise --ledger <RECORDS>/fastloop/CQR_LEDGER.jsonl --scope cqr_fastloop --job fastloop:<label> --timeout 330 --mem-gib 8 -- <command>`. The 300 s bound is enforced INSIDE the runner (one absolute deadline; every subprocess hard wait derived from the remaining allowance; the report's `elapsed_s` / `within_cap` are the evidence); the supervisor's 330 s is the outer kill, never the bound.

Invariants (v3; repair-2 review CQR-AF2-03..07): the output directory must be EMPTY (fresh private snapshot set; a pre-existing snapshot is refused); every snapshot holds exactly the declared files and is verified after copying (hashes AND absences; the manifest's absent-evidence marker normalized to the reader's sha256(b'0')); the consumed binding is compared with the pinned row at the worker, checker and oracle boundaries; the candidate / baseline identities (full inventory, cqr scope, kernels) are PINNED at iteration start and enforced before every launch, after every verification (in-process re-hash of the pinned file set) and by subprocess before final success (any drift = BUILD_DRIFT, even with an unchanged answer); check_cli verifies against the PINNED identity, never the current build against itself; worker records must have the required fields and a recognized terminal (status, outcome) pair (a `{}` or unknown outcome = WORKER_PROTOCOL stop); worker, checker AND oracle must exit normally (a record followed by an abnormal exit is discarded: VERIFIER_FAULT / ORACLE_FAULT; rc / timeout / hard wait recorded beside every result); a failed checker passes no negative control; a failed oracle populates no EXACT cache; truth cache hits must be listed in the trusted preparation index (TRUTH_INDEX.json, written once by truth_prep; its sha256 recorded in TRUTH_PREP.json and in every report) -- the self-contained record seal alone is NOT independent authentication (trusted-writer boundary stated in truth.py); in-run computations never persist into an indexed cache. Invariants carried from v2: one absolute deadline (now covering identity / git / every nested hard wait); durable report after every cell and in `finally`; three separate verdicts; two labelled evidence channels (VERIFIED predicates vs `_OBSERVED` predicates from the sidecar); nothing is PASS. SCOPE of the ladder: the pinned n24 rungs are difficult for the protected enumerator (reference.Reference), not for exact inference in general (the elimination oracle solves them in milliseconds): mechanism qualification, never a general approximate-inference advantage.

`cex/cqr_amend/amend_verification.py` (v2): the SUCCESSOR VERIFICATION CHAIN prepare -> execute -> report -> closeout for a completed shard: the frozen gate's global preflight (unique planned / observed ids, exact set equality), the HISTORICAL AUTHORITY (ledger RECEIPT rows + the original gate's gated set: receipt / output / dependency hashes, walls) required equal at preparation and again at execution, the tool identity (cqr_amend/*.py + gbidi/supervise.py) and verifier identity enforced at every step, immutable attempts, a gate result schema-compatible with the frozen gate, the frozen report with `--gate/--out-dir`, a fail-closed closeout bound to the VERIFIER's qualification record; `--fresh` for a shard that has no gate yet; every step must run under gbidi.supervise. `execute` on the real A1 only after review.
